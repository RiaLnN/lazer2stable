# Дизайн-документ: lazer2stable (v2.0 Rust)

## 1. Контекст и цель (Intent & Why)

**osu! lazer** — современная версия ритм-игры osu!, использующая базу данных MongoDB Realm (`client.realm`) и плоское контентно-адресуемое хранилище файлов (файлы переименованы в их SHA-256 хэши в директории `files/xx/xxxx...`).  
**osu! stable** — классическая версия игры, требующая файлы карт в формате `.osz` / распакованных папок в `Songs/` и скины в формате `.osk` / папок в `Skins/`.

В osu! lazer отсутствует встроенная функция экспорта всей библиотеки карт и скинов обратно в osu! stable.
Цель проекта — создать быстрое, надежное, кроссплатформенное приложение с удобным графическим интерфейсом (GUI) и консольным интерфейсом (CLI), переписанное на Rust, позволяющее игрокам легко и в один клик перенести свои карты и скины из lazer в stable.

---

## 2. Цели, не-цели и анти-цели

### Цели (Goals):
1. **Единый стек на Rust**: Ядро (`lazer2stable-core`), CLI (`lazer2stable-cli`) и GUI (`lazer2stable-gui`).
2. **Перенос карт**:
   - Основной режим: скачивание актуальных `.osz` из сети через зеркала (catboy, nerinyan, osudirect) по `online_id` с поддержкой возобновления, пропуска уже скачанных/установленных карт и отслеживания rate limits (`Retry-After`).
   - Опциональный режим: локальная офлайн-сборка карт из локального кэша `files/` lazer (для карт, которых нет в онлайне, или при отсутствии интернета).
3. **Перенос скинов**:
   - Полная офлайн-сборка пользовательских скинов из `client.realm` + `files/`.
   - Упаковка в валидный `.osk` (zip-архив с сохранением оригинальных путей файлов, `skin.ini`, текстур, звуков) и копирование в директорию `Skins/` в stable.
4. **Удобный графический интерфейс (GUI)**:
   - Построен на `egui` / `eframe`.
   - Структура вкладок (Вариант B: «Карты», «Скины», «Настройки») с глобальной нижней панелью статуса, прогресс-баром и кнопкой запуска.
   - Строгий визуальный стиль с векторными SVG-иконками (без эмодзи).
5. **Конфигурация**:
   - Хранение всех настроек и путей в `config.toml`.
   - Автоматическое обнаружение путей установки lazer и stable для Windows и Linux.
6. **Надежное чтение Realm**:
   - Автономный мост на C# (`realm-bridge`), использующий официальный `Realms` NuGet пакет для динамического чтения схемы lazer без риска несовместимости версий базы данных.
7. **English Language Everywhere**:
   - Весь интерфейс (GUI): названия вкладок, кнопки, подсказки, статус-сообщения, диалоги.
   - Консоль (CLI): справка, логи, сообщения об ошибках.
   - Исходный код: все комментарии, docstrings, документация и названия переменных/функций строго на английском языке.

### Не-цели (Non-Goals):
1. Обратный перенос из stable в lazer (lazer сам умеет нативно импортировать библиотеки stable).
2. Поддержка браузерных / web-view оболочек (Electron, Tauri) — приложение должно быть минималистичным, нативным и запускаться мгновенно.
3. Модификация или запись в базу `client.realm` (доступ только строго Read-Only).

### Анти-цели (Anti-Goals):
1. Блокировка UI потока во время длительных операций экспорта/скачивания (все сетевые и дисковые задачи выполняются в фоне с передачей событий через каналы).
2. Повреждение файлов существующей установки osu! stable или lazer.
3. Спам сетевых запросов и игнорирование HTTP 429.

## 4. Спецификация компонентов

### 4.1. C# Realm Bridge (`realm-bridge`)
Выполняет роль безопасного парсера `client.realm` и выдает JSON в stdout:
1. `dump-beatmaps --realm <path>`:
   - Читает коллекцию `BeatmapSet`.
   - Игнорирует записи с `DeletePending == true` и `OnlineID <= 0`.
   - Выводит JSON массив: `[ { "online_id": int, "title": string, "artist": string, "files": [ { "filename": string, "hash": string } ] } ]`.
2. `dump-skins --realm <path>`:
   - Читает коллекцию `SkinInfo`.
   - Игнорирует записи с `DeletePending == true`.
   - Выводит JSON массив: `[ { "id": string, "name": string, "creator": string, "files": [ { "filename": string, "hash": string } ] } ]`.

### 4.2. Конфигурация (`config.toml`)
```toml
[paths]
lazer_dir = ""        # Автодетект или ручной путь
stable_dir = ""       # Автодетект или ручной путь
realm_path = ""       # Если пусто -> lazer_dir/client.realm
songs_dir = ""        # Если пусто -> stable_dir/Songs
skins_dir = ""        # Если пусто -> stable_dir/Skins
cache_dir = "cache"   # Кэш скачанных .osz / временных файлов

[beatmaps]
enabled = true
source_mode = "network"    # "network" или "local"
no_video = false
skip_existing = true
concurrency = 4
sources = ["catboy", "nerinyan", "osudirect"]
# osu_session = ""         # Опционально для официального сайта

[skins]
enabled = true
export_as_osk = true       # Сохранять .osk в папку экспорта
unpack_to_stable = true    # Сразу распаковывать в stable/Skins/
```

### 4.3. Логика переноса скинов
1. Из `dump-skins` получаем список файлов скина с их оригинальными именами (`skin.ini`, `hitcircle.png` и т.д.) и SHA-256 хэшами.
2. В хранилище lazer файл лежит по пути: `{lazer_dir}/files/{hash[0..1]}/{hash[0..2]}/{hash}` (или `{hash[0..1]}/{hash}`).
3. Для каждого скина:
   - Создается архив ZIP с расширением `.osk`.
   - В корень архива добавляются файлы под их `filename`.
   - Если включено `unpack_to_stable`: файлы скина распаковываются в папку `{stable_dir}/Skins/{SkinName}`.

### 4.4. Логика переноса карт
1. Из `dump-beatmaps` получаем список сетов с `online_id`.
2. Проверка наличия сета в `{stable_dir}/Songs/` (по префиксу id) и в локальном кэше `.osz`.
3. Если режим `network`:
   - Асинхронное скачивание через пул воркеров (`concurrency`).
   - Поддержка зеркал с ротацией при ошибках.
   - Учет заголовков `Retry-After` при HTTP 429.
   - Распаковка в `Songs/` или перемещение `.osz`.
4. Если режим `local`:
   - Сборка `.osz` (zip) из файлов, перечисленных в сете карты в Realm, с извлечением из `files/`.

### 4.5. Графический интерфейс (`egui`)
1. **Вкладка 1: Карты (Beatmaps)**
   - Выбор режима: сетевая загрузка (зеркала) / локальная сборка.
   - Опции: пропуск уже имеющихся, исключение видео.
   - Сводка: найдено X карт, размер, статус.
2. **Вкладка 2: Скины (Skins)**
   - Список обнаруженных пользовательских скинов с чекбоксами.
   - Кнопка «Выбрать все / Снять все».
   - Опция распаковки в папку скинов stable.
3. **Вкладка 3: Настройки (Settings)**
   - Статус путей lazer и stable с зеленой/красной индикацией и кнопками выбора папки.
   - Настройка потоков (concurrency) и зеркал.
   - Кнопка «Сохранить конфигурацию».
4. **Нижняя панель (Action & Status Bar)**
   - Отображение текущего этапа и прогресс-бара (`N / Total`).
   - Кнопки: «Начать перенос» / «Пауза / Отмена».
   - Кнопка раскрытия лога операций (выдвижное текстовое поле со строками логов).

## 5. Платформенные особенности и автодетект путей

### Windows:
- Lazer: `%APPDATA%\osu`
- Stable: `%LOCALAPPDATA%\osu!`

### Linux:
- Lazer Native: `~/.local/share/osu`
- Lazer Flatpak: `~/.var/app/sh.ppy.osu/data/osu`
- Stable: поиск в стандартных префиксах Wine/Proton (`~/.wine/drive_c/osu!`, Lutris, Bottles).

## 7. Технические решения разработчика (Builder Calls)
1. **Способ доставки карт в stable:** В конфигурации и интерфейсе поддерживаются оба режима (`extract` — распаковка прямо в `Songs/`, и `open` — запуск каждого `.osz` через `osu!.exe`). По умолчанию выбран `extract`, так как он работает в десятки раз быстрее и надежнее при большом количестве карт.
2. **Именование карт без OnlineID (локальные):** Если карта собирается локально и не имеет официального OnlineID (`<= 0`), папка в `Songs/` именуется как `[local] {Artist} - {Title}` или `{Hash[0..8]} {Artist} - {Title}` для исключения коллизий.
3. **Порядок поиска `realm-bridge`:** Rust-ядро ищет бинарник моста по цепочке:
   - Явный путь из `config.toml` (если указан);
   - Рядом с исполняемым файлом приложения (`./realm-bridge` / `realm-bridge.exe`);
   - В директории проекта `bridge/bin/Release/net8.0/realm-bridge`;
   - Фолбэк: вызов `dotnet run --project bridge -- ...`, если установлен .NET SDK.
